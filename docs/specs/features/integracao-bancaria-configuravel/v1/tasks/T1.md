## 2. Objetivo da Task
Estabelecer a camada de domínio agnóstica de provedor: dataclasses canônicas, o enum `SituacaoBoleto` (preservando o texto cru ao lado), a porta `AdaptadorCobrancaBancaria` e o `registry` que resolve provedor → adaptador. Nenhum acesso a `frappe` nesta camada.

---

## 3. Descrição Detalhada
Criar o pacote `cobranca_bancaria/` com três módulos de domínio puro (sem import de `frappe`):

- `modelo.py` — dataclasses do §4.2 do tech_spec: `CredenciaisIntegracao`, `CertificadoDigital`, `ContaBancaria`, `Pagador`, `BoletoCanonico`, `ResultadoEmissao`, `ResultadoBaixa`, `ResultadoConsulta`, `ResultadoToken`. Enum `SituacaoBoleto` com os 6 valores (`EMITIDO`, `BAIXADO`, `LIQUIDADO`, `VENCIDO`, `CANCELADO`, `DESCONHECIDO`); o texto cru do provedor é preservado em campo separado do resultado, nunca sobrescrito (D5).
- `porta.py` — ABC `AdaptadorCobrancaBancaria` com exatamente os cinco métodos nomeados **literalmente** na `Decision` da ADR-0001: `obter_token()`, `emitir(boleto)`, `solicitar_baixa(ref)`, `confirmar_baixa(ref)`, `consultar(ref)`. Todos recebem/retornam apenas tipos canônicos.
- `registry.py` — `obter_adaptador(credenciais)` resolve `credenciais.provedor` → classe do adaptador. Hoje só `"sicoob"`. Provedor desconhecido → erro explícito nomeando o provedor (`PROVEDOR_DESCONHECIDO`), nunca `None` silencioso.
- Campos sem equivalente canônico vivem em `parametros_provedor` (dict) — escape explícito da ADR-0001; nenhum vocabulário de provedor no núcleo.

O registry importa a classe do adaptador de forma tardia (lazy) para não puxar `requests_pkcs12` na camada de domínio.

### 6.6 Detalhamento dos Casos de Teste

#### CT-001 — Enum canônico de situação do boleto preserva o texto cru do provedor ao lado
- **Tipo/Camada**: UNITARIO · unit · CA CA-17
- **Invariante**: Para qualquer texto de situação devolvido pelo provedor, o mapeamento canônico produz exatamente um dos 6 valores do enum (EMITIDO, BAIXADO, LIQUIDADO, VENCIDO, CANCELADO, DESCONHECIDO) e preserva o texto cru original ao lado, sem perdê-lo nem sobrescrevê-lo — mesmo para texto não reconhecido.
- **Pré-condições**: Função de mapeamento canônico implementada e importável isoladamente do adaptador HTTP
- **Entrada**: {"descricao": "Tabela parametrizada de textos crus do provedor Sicoob", "valores": {"casos": [{"texto_cru": "Em aberto", "esperado_enum": "EMITIDO"}, {"texto_cru": "Baixado", "esperado_enum": "BAIXADO"}, {"texto_cru": "Liquidado", "esperado_enum": "LIQUIDADO"}, {"texto_cru": "Vencido", "esperado_enum": "VENCIDO"}, {"texto_cru": "Cancelado", "esperado_enum": "CANCELADO"}, {"texto_cru": "Protestado"
- **Passos**: Para cada linha da tabela, invocar a função de mapeamento canônico com o texto_cru.; Capturar o par (enum_canonico, texto_cru_preservado) retornado.
- **Esperado**: "enum_canonico == esperado_enum da linha E texto_cru_preservado == texto_cru de entrada (idêntico, sem normalização que perca informação), para todas as 7 linhas."
- **Negative companion**: self — texto de situação não mapeado (ex.: 'Protestado', string vazia, None) → mapeamento cai em DESCONHECIDO (nunca lança exceção) e o campo de texto cru contém o valor original exatamente como recebido
- **Execução real**: none (fronteira HTTP mockada — provedor não é chamado)

#### CT-002 — Registry resolve o adaptador correto para um provedor conhecido
- **Tipo/Camada**: UNITARIO · unit · CA CA-17
- **Invariante**: Dado o nome de um provedor cadastrado no registry, a resolução retorna uma instância que implementa integralmente a porta AdaptadorCobrancaBancaria (obter_token, emitir, solicitar_baixa, confirmar_baixa, consultar).
- **Pré-condições**: Registry populado com ao menos o adaptador Sicoob
- **Entrada**: {"descricao": "Identificador de provedor 'sicoob'", "valores": {"provedor": "sicoob"}}
- **Passos**: Chamar a função de resolução do registry com provedor='sicoob'.; Verificar que o objeto retornado expõe os 5 métodos da porta.
- **Esperado**: "Retorna instância não-nula cujo tipo implementa AdaptadorCobrancaBancaria; hasattr(obter_token, emitir, solicitar_baixa, confirmar_baixa, consultar) == True para todos."
- **Negative companion**: CT-003 — nome de provedor não cadastrado → erro explícito de provedor desconhecido, sem devolver adaptador parcial
- **Execução real**: none (fronteira HTTP mockada — provedor não é chamado)

#### CT-003 — Registry recusa provedor desconhecido com erro explícito
- **Tipo/Camada**: UNITARIO · unit · CA CA-17
- **Invariante**: Resolver um provedor não cadastrado no registry nunca retorna um adaptador parcial ou None silencioso — sempre lança/retorna um erro explícito nomeando o provedor.
- **Pré-condições**: Registry populado apenas com 'sicoob'
- **Entrada**: {"descricao": "Identificador de provedor inexistente", "valores": {"provedor": "banco_inexistente_xyz"}}
- **Passos**: Chamar a função de resolução do registry com provedor='banco_inexistente_xyz'.
- **Esperado**: "Levanta exceção/erro de negócio explícito citando 'banco_inexistente_xyz' como provedor desconhecido; nenhum objeto adaptador é construído."
- **Negative companion**: self — provedor='banco_inexistente_xyz' → erro contém o texto 'banco_inexistente_xyz' e nenhuma instância é retornada
- **Execução real**: none (fronteira HTTP mockada — provedor não é chamado)
