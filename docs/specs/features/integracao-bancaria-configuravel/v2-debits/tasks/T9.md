## 4. Detalhes de Implementação

### 4.1 Contexto do Débito

**Origem**: task `T13` da `v1` — registrado em `docs/specs/features/integracao-bancaria-configuravel/v1/_run/run-report.md` (linha 77).

**Descrição original**: o loop faz `for page in reader.pages: writer.add_page(page)` e só então captura exceção. Se um PDF **multipágina** corromper na página N, as páginas 1..N-1 **já foram adicionadas** ao `writer` e, no `except`, o boleto ainda é anexado a `ausentes`. Resultado: o consolidado conteria páginas órfãs de um boleto reportado como ausente — contrariando a semântica de RN-09 ("ausente = fora do consolidado").

**Janela hoje é vazia na prática**: os boletos do MVP têm 1 página, então a falha ocorre na construção do `PdfReader` ou na 1ª página, **antes** de qualquer `add_page`. O débito é preventivo.

**Categoria**: `error_handling` (BAIXO)

**Classificação do especialista**: `perfumaria`
**Justificativa**: "Custo: ~12min (bufferizar páginas por boleto num writer temporário antes do merge final, mais teste de regressão para PDF corrompido na página N). Risco: baixo — janela hoje é vazia na prática (boletos do MVP têm 1 página, falha ocorre antes de qualquer add). Valor real existe mas não é urgente; melhor tratar junto de um refactor da montagem do consolidado."
**Custo estimado**: ~12min
**Risco de regressão**: `baixo`

> **Incluído por decisão explícita do usuário** (cleanup completo), ciente de que o especialista o classificou como perfumaria.
>
> Nota: a classificação previa também um "teste de regressão para PDF corrompido na página N". Esta versão **não cria testes** (política de cleanup — ver §5). Se quiser essa cobertura, ela deve virar uma task de feature própria, não de débito.

### 4.2 Correção

- [x] Em `montar_pdf_consolidado`, montar as páginas de **cada boleto** num buffer temporário (ex.: lista de páginas ou `PdfWriter` intermediário).
- [x] Só mesclar o buffer no writer final **após** ler o boleto inteiro com sucesso.
- [x] No `except`, **descartar** o buffer parcial antes de anexar o identificador a `ausentes`.
- [x] Preservar o comportamento do caminho feliz: mesma ordem de páginas, mesma contagem, mesma lista de ausentes para os cenários já cobertos.

### 4.3 Guardrails de Execução

**DEVE**:

- Preservar a **ordem** das páginas no consolidado (a ordem dos boletos e das páginas dentro de cada boleto não pode mudar).
- Manter a semântica de `ausentes`: todo boleto que não contribuiu com páginas aparece lá, por identificador — nunca omitido silenciosamente (RN-09).
- Manter a montagem **em memória** (D6) — nada gravado em disco/File.
- Rodar a suíte completa antes de retornar a task. **CT-020 é o oráculo** (2 boletos com PDF → 2 páginas; 1 sem PDF → lista de ausentes com o 3º).

**NÃO DEVE**:

- NÃO alterar o contrato de retorno de `montar_pdf_consolidado` (bytes + lista de ausentes).
- NÃO persistir o consolidado (D6 — em memória).
- NÃO antecipar **D-007/T7** nem **D-008/T8** no mesmo arquivo.
- NÃO adicionar testes novos (mesmo que a classificação do especialista mencionasse um — ver nota em §4.1).
