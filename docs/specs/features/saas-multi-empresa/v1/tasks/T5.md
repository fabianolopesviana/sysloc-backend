## 2. Objetivo da Task
Criar o módulo de domínio de imóvel concentrando a regra de metragem e os dois endpoints que operam sobre imóvel, preservando os nomes curtos por alias.

---

## 3. Descrição Detalhada
Três regras migram para o **mesmo arquivo** (`imovel/service.py`), por isso formam uma task só (Regra 3 de decomposição):

1. **Regra de metragem** → `calcular_metragem_total(doc)`, registrada em `doc_events` como `Imovel.before_save`. São ~10 linhas: soma a metragem dos cômodos filhos e grava no campo do pai. Sem I/O, sem efeito colateral externo.
2. **`all_imoveis`** → função `@frappe.whitelist()`, com alias registrado.
3. **`atualizar_comodo`** → idem.

**Ordem obrigatória de migração de cada endpoint** (tech_spec §5.1, verificada em `frappe/handler.py:62-72`): registrar a função **e** o alias no mesmo passo; comprovar equivalência; **só então** desativar o Server Script. Nunca desativar antes — o override precede a busca por Server Script e usa o nome já traduzido, então o alias sozinho já assume o atendimento. Inverter a ordem abriria janela em que o endpoint não responde por ninguém, com o aplicativo em produção chamando esses caminhos.

Reversão: remover o alias devolve o atendimento ao Server Script original imediatamente, sem redeploy.

### 6.6 Detalhamento dos Casos de Teste

#### CT-012 — calcular_metragem_total soma corretamente a metragem dos cômodos filhos

- **Tipo**: UNITARIO | **Categoria**: caminho_feliz | **Camada**: Serviço de domínio (imovel/service.py)
- **Arquivo**: `app-sync/locacao_automation/locacao_automation/tests/test_caracterizacao_metragem.py`
- **Invariante**: Para um `Imovel` com N cômodos filhos, `calcular_metragem_total` grava no campo do pai a soma exata das metragens dos filhos — nenhuma perda, nenhuma duplicação.
- **Fronteira real de execução**: none
- **Pré-condições**: Doc `Imovel` in-memory com 3 cômodos filhos de metragens 20.5, 15.0 e 9.5
- **Passos**:
  1. Montar `doc` com os 3 cômodos filhos
  2. Chamar `calcular_metragem_total(doc)` (ou disparar `before_save`)
  3. Ler o campo de metragem total do pai
- **Resultado esperado**: Campo de metragem total do `Imovel` == 45.0 (20.5+15.0+9.5), exatamente
- **Companheiro negativo**: `CT-013` — entrada: Imovel sem cômodos (lista vazia) ou cômodo com metragem nula → soma resultante é 0 (ou o sentinela documentado), sem lançar exceção
- **Observações**: Função pura (~10 linhas), sem I/O — unit real, sem mock.

#### CT-013 — Metragem trata Imovel sem cômodos ou com metragem nula sem quebrar

- **Tipo**: UNITARIO | **Categoria**: fronteira | **Camada**: Serviço de domínio (imovel/service.py)
- **Arquivo**: `app-sync/locacao_automation/locacao_automation/tests/test_caracterizacao_metragem.py`
- **Invariante**: A ausência de cômodos filhos ou um cômodo com metragem `None` não faz `calcular_metragem_total` lançar exceção — a soma degrada para um valor seguro e documentado.
- **Fronteira real de execução**: none
- **Pré-condições**: Doc `Imovel` in-memory sem cômodos filhos (lista vazia); Variante: 1 cômodo com `metragem=None`
- **Passos**:
  1. Montar `doc` sem cômodos
  2. Chamar `calcular_metragem_total(doc)`
  3. Repetir com 1 cômodo de metragem `None`
- **Resultado esperado**: Ambos os casos retornam/gravam 0 (sem exceção lançada); nenhum `TypeError`/`AttributeError` propagado
- **Companheiro negativo**: `self` — entrada: este é o companion negativo de CT-012 → ver resultado_esperado
- **Observações**: Caso extremo herdado do comportamento atual — não introduz validação nova (equivalência, não melhoria).

#### CT-014 — Regra de metragem migrada reproduz o valor de referência capturado antes da migração

- **Tipo**: INTEGRACAO | **Categoria**: integracao | **Camada**: Serviço de domínio (imovel/service.py) — caracterização (D2)
- **Arquivo**: `app-sync/locacao_automation/locacao_automation/tests/test_caracterizacao_metragem.py`
- **Invariante**: Para o conjunto de `Imovel` reais usado como referência (capturado com o Server Script original ainda ativo), `calcular_metragem_total` produz exatamente os mesmos valores — a equivalência de RN-08 é comprovada por caracterização, não por leitura de código.
- **Fronteira real de execução**: db
- **Pré-condições**: Referência versionada capturada ANTES da migração (valores reais dos `Imovel` de produção, com o Server Script original ainda ativo)
- **Passos**:
  1. Carregar a referência versionada (arquivo/constante do teste)
  2. Para cada `Imovel` do conjunto, chamar `calcular_metragem_total`
  3. Comparar valor obtido com o valor de referência, um a um
- **Resultado esperado**: Para 100% dos imóveis do conjunto de referência, `calcular_metragem_total(imovel) == referencia[imovel.name]`, sem tolerância de arredondamento além da precisão decimal já usada em produção
- **Companheiro negativo**: `self` — entrada: qualquer divergência de valor entre a referência e o resultado migrado É o modo de falha desta invariante → diferença de qualquer imóvel do conjunto de referência reprova o teste (equivalência quebrada, RN-08 bloqueia a substituição da regra original)
- **Observações**: É o teste que abre caminho para desativar o Server Script original (RN-08) — só conclui quando este teste está verde.

#### CT-021 — all_imoveis retorna lista de imóveis por conjunto no mesmo formato de resposta anterior

- **Tipo**: INTEGRACAO | **Categoria**: caminho_feliz | **Camada**: Endpoint HTTP whitelisted (imovel/service.py)
- **Arquivo**: `app-sync/locacao_automation/locacao_automation/tests/test_imovel_api.py`
- **Invariante**: O endpoint `all_imoveis` migrado retorna a mesma estrutura de resposta (lista de imóveis agrupada por conjunto) que o Server Script original — nenhuma quebra de contrato para o SPA (CA-06).
- **Fronteira real de execução**: db
- **Pré-condições**: Ao menos 2 `Conjunto` com `Imovel` vinculados existem; Usuário autenticado com papel `Servico App`
- **Passos**:
  1. Autenticar como usuário de serviço
  2. Chamar `all_imoveis()`
  3. Inspecionar a estrutura retornada
- **Resultado esperado**: Resposta é uma lista/dict agrupado por `conjunto`, cada imóvel presente com os mesmos campos-chave documentados em tech_spec §4.1 (mesma forma que o SPA já consome)
- **Companheiro negativo**: `self` — entrada: usuário sem permissão de leitura em `Imovel`/`Conjunto` → chamada retorna 403 (permissão negada), sem vazar dados de outros conjuntos
- **Pré-condição privilegiada**: O endpoint exige o token do usuário de serviço (contexto autenticado), não uma sessão de usuário comum sem papel. — caminho legítimo: Criar `User` real com `add_roles('Servico App')`, `frappe.set_user(user.name)` e restauração via `addCleanup(lambda: frappe.set_user('Administrator'))` — o mesmo caminho já usado em `test_patch_criar_papel_servico_app.py::TestPermissaoEfetivaServicoApp._criar_usuario_servico_app`.
- **Observações**: Novo arquivo justificado: `test_endpoints_migrados.py` (tech_spec) é escopado à resolução do alias (CT-019/020), não ao comportamento de cada função.

#### CT-024 — atualizar_comodo persiste alteração e retorna confirmação

- **Tipo**: INTEGRACAO | **Categoria**: caminho_feliz | **Camada**: Endpoint HTTP whitelisted (imovel/service.py)
- **Arquivo**: `app-sync/locacao_automation/locacao_automation/tests/test_imovel_api.py`
- **Invariante**: Com payload válido, `atualizar_comodo` persiste a alteração no `Comodo` correspondente e retorna confirmação (200) — a metragem do imóvel pai é recalculada como efeito colateral esperado (before_save).
- **Fronteira real de execução**: db
- **Pré-condições**: `Imovel` com ao menos 1 `Comodo` filho existente
- **Passos**:
  1. Autenticar como usuário de serviço
  2. Chamar `atualizar_comodo` com payload válido
  3. Reconsultar o `Comodo` e o `Imovel` pai
- **Resultado esperado**: Status 200; `Comodo.metragem == 12.0` persistido; metragem total do `Imovel` pai recalculada refletindo o novo valor
- **Companheiro negativo**: `CT-025` — entrada: payload de cômodo malformado (campo obrigatório ausente) → 417 com erro de validação
- **Pré-condição privilegiada**: Endpoint exige token do usuário de serviço. — caminho legítimo: Mesmo caminho de CT-021.
- **Observações**: Cruza com a regra de metragem (CT-012/014) como efeito colateral observável — não duplica o teste da regra, apenas confirma o disparo via endpoint.

#### CT-025 — atualizar_comodo com payload inválido retorna 417

- **Tipo**: INTEGRACAO | **Categoria**: tratamento_erro | **Camada**: Endpoint HTTP whitelisted (imovel/service.py)
- **Arquivo**: `app-sync/locacao_automation/locacao_automation/tests/test_imovel_api.py`
- **Invariante**: Payload de cômodo malformado (campo obrigatório ausente ou tipo inválido) é rejeitado com 417, sem persistir alteração parcial.
- **Fronteira real de execução**: db

- **Passos**:
  1. Autenticar como usuário de serviço
  2. Chamar `atualizar_comodo` com payload malformado
  3. Reconsultar o `Comodo` original
- **Resultado esperado**: Status 417; `Comodo.metragem` permanece com o valor original (nenhuma escrita parcial)
- **Companheiro negativo**: `self` — entrada: este é o companion negativo de CT-024 → ver resultado_esperado
- **Pré-condição privilegiada**: Mesma precondição de CT-024. — caminho legítimo: Mesmo caminho de CT-021.
- **Observações**: Preserva o mapeamento de erro 417 documentado em tech_spec §10.1 ('Falha de validação de payload').
