## 2. Objetivo da Task
Levar as 6 rotinas agendadas e os scripts que elas invocam para o repositório, instaláveis por procedimento idempotente, com retenção de registros definida.

---

## 3. Descrição Detalhada
Hoje a configuração de agendamento existe apenas no servidor, e **dois dos seis scripts não estão versionados em lugar nenhum**.

Escopo (ADR-0005):

1. Mover os 6 scripts para `deploy/bin/` — os 4 que hoje vivem na raiz do projeto e os 2 que vivem em diretório de sistema.
2. **Condição de entrada, não ajuste posterior**: o script de backup carrega a senha do banco em texto plano. Extrair o segredo para configuração não versionada **antes** de o script entrar no repositório. Nenhum script entra carregando credencial.
3. Criar a definição de agendamento em `deploy/cron/`, com os 6 horários reais coletados — incluindo a correção do horário que a documentação registrava errado.
4. Criar o instalador idempotente, que posiciona a definição em `/etc/cron.d` e os scripts no destino do sistema. Executar duas vezes produz o mesmo estado, sem duplicar entrada.
5. **Trava de execução** na rotina de maior frequência (executa a cada minuto, hoje sem proteção), no mesmo mecanismo que a rotina de sincronização já usa.
6. **Retenção**: saída única em `/var/log`; os scripts param de escrever no diretório do projeto. Política de rotação versionada em `deploy/cron/`.

## 7. Notas / Observações

**A extração da credencial é bloqueante.** Versionar o script de backup como está publicaria a senha do banco no repositório — exatamente a classe de problema que a contenção anterior existiu para conter.

**Independente das demais**: não toca código do app nem estrutura de dados. Poderia rodar em paralelo à Fase 1 se o usuário quiser antecipá-la.
