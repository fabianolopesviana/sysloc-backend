## 4. Detalhes de Implementação

### 4.1 Contexto do Débito

**Origem**: task `T1` de `v2-debits` — registrado em `docs/specs/features/contencao-credencial-exposta/v2-debits/_run/run-report.md` (bloco `### D1`, linha 36). Emitido pelo QA em **duas rodadas consecutivas**.

**Descrição original**: nenhum dos 168 testes assere que `hooks.py` declara `after_migrate` apontando para `locacao_automation.patches.v1_0.criar_papel_servico_app.execute`. Apagar essa lista deixaria a suíte inteiramente verde. Três modos de falha ficam descobertos:

1. **hook removido** de `hooks.py`;
2. **typo no dotted path** — módulo ou função renomeados sem atualizar a string;
3. **função resolvida que deixou de convergir**.

Hoje os três só apareceriam num `bench migrate` de produção.

**Por que importa apesar de `BAIXO`**: o `after_migrate` é o **único** mecanismo que impede permissão residual de sobreviver no papel `Servico App` — cuja credencial de API está publicada no bundle JavaScript por desenho. O `patches.txt` não cobre: `install_app` chama `set_all_patches_as_completed`, que marca todos os patches do app como concluídos **sem executá-los** (`frappe/installer.py:307-308`).

**Por que não foi corrigido antes**: a §4.3 da task de origem proibia explicitamente "adicionar testes além do CT exigido em §4.2". O executor obedeceu o guardrail; o QA registrou a lacuna como débito.

**Categoria**: `tests` (BAIXO)

**Classificação do especialista**: `recomendado_corrigir`
**Justificativa**: teste barato que fecha um gap real de detecção de regressão num hook que protege exposição de credencial via internet. Resolvendo o dotted path dinamicamente (não hardcoded), fica desacoplado do path que D-002 poderia mudar no futuro, então não cria dívida cruzada.
**Custo estimado**: ~15min
**Risco de regressão**: `baixo`

### 4.2 Correção

- [x] Acrescentar 1 teste em `tests/test_patch_criar_papel_servico_app.py` que:
      1. obtenha os hooks pelo mecanismo real: `frappe.get_hooks("after_migrate")`;
      2. **filtre** os do app (`[h for h in hooks if h.startswith("locacao_automation.")]`) e asserte a lista exata — falha se o hook for removido;
      3. **resolva** o dotted path com `frappe.get_attr(alvo)` — falha com typo no path (módulo ou função renomeados);
      4. semeie um `Custom DocPerm` residual do papel `Servico App` (o mesmo vetor de CT-063: `permlevel=1` num dos 9 DocTypes);
      5. **asserte que a semeadura pegou** — sem isso o teste passa por não ter semeado nada;
      6. chame a **função resolvida** (`alvo_resolvido()`), **não** o `execute` importado no topo do arquivo;
      7. asserte que o resíduo sumiu e que a contagem voltou a **exatamente 9**.

> **O passo 6 é o que dá valor ao teste.** Chamar o import direto testaria a função, que CT-063 já cobre. Chamar o símbolo **resolvido pelo hook** testa a cadeia inteira: `hooks.py` → `get_hooks` → `get_attr` → função convergente. É o que o framework faz em `frappe/migrate.py:145-147`.

- [x] Documentar o CT no docstring do arquivo de teste, seguindo a convenção de rastreabilidade já usada lá.
