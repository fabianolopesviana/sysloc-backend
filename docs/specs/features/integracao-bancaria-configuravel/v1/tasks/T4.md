## 2. Objetivo da Task
Fonte única de resolução da configuração ativa (substitui as 5 cópias de `_obter_configuracao_ativa`), devolvendo `CredenciaisIntegracao`, com fallback de leitura para a configuração legada e para o certificado montado em caminho fixo enquanto nada for enviado pela tela.

---

## 3. Descrição Detalhada
Criar `cobranca_bancaria/configuracao.py`:

- `resolver_credenciais() -> CredenciaisIntegracao` — lê a `Configuracao Integracao Bancaria` ativa; valida **exatamente uma ativa** por provedor (erro estruturado único: `CONFIGURACAO_AUSENTE` / `CONFIGURACAO_DUPLICADA`, mesmo shape nos 5 pontos de consumo). Obtém a senha via `get_password`. Resolve o certificado: se `certificado_arquivo` presente → File privado; senão → `pfx_path_legado` montado em `/run/secrets/sicoob` (RN-10), com `origem` = `upload`|`legado`. Ausência de ambos → `CERTIFICADO_LEGADO_INDISPONIVEL`, erro de negócio sem stacktrace.
- O erro estruturado unificado substitui a divergência atual (1 dict + 4 strings) — retorno `{success: False, error_code, message, details}`.
- Guarda de validade (RN-07): a resolução expõe `certificado.validade_fim` para o pré-check das operações; o bloqueio em si é aplicado por quem emite (T10).

Enquanto a config canônica não estiver populada (antes do Patch 1), o resolver cai na legada — por isso o fallback cobre também a leitura da DocType legada.

### 6.6 Detalhamento dos Casos de Teste

#### CT-011 — RN-01: existe no máximo uma configuração bancária ativa por provedor (zero ativas / mais de uma ativa retornam erro estruturado único)
- **Tipo/Camada**: INTEGRACAO · service-integration · CA CA-01, CA-05
- **Invariante**: RN-01: nenhuma operação de cobrança ocorre sem exatamente uma configuração ativa; zero configurações ativas OU mais de uma configuração ativa para o mesmo provedor retornam o MESMO shape de erro estruturado (não mais a divergência dict-vs-string entre os 5 módulos).
- **Pré-condições**: Site de teste do Frappe com a nova DocType de configuração canônica migrada (D1)
- **Entrada**: {"descricao": "3 cenários de contagem de configuração ativa", "valores": {"casos": [{"cenario": "zero_ativas", "qtd_ativas": 0}, {"cenario": "uma_ativa", "qtd_ativas": 1}, {"cenario": "duas_ativas", "qtd_ativas": 2}]}}
- **Passos**: Inserir N registros de configuração (0, 1 ou 2) marcados como ativos no site de teste real.; Chamar a função unificada de resolução de configuração ativa.
- **Esperado**: "qtd_ativas=1: retorna a configuração sem erro. qtd_ativas=0 e qtd_ativas=2: retornam erro estruturado {success: False, message: ...} com o MESMO shape entre si."
- **Negative companion**: self — 0 registros ativos; 2 registros ativos simultaneamente → erro estruturado {success: False, message: <texto>} em ambos os cenários, idêntico em shape entre si e entre os 5 pontos de consumo (auth/emissão/cons
- **Execução real**: db (fronteira HTTP mockada — provedor não é chamado)

#### CT-025 — CA-16/RN-10: enquanto nenhum certificado for enviado pela tela, emissão/baixa/consulta continuam operando com a credencial pré-existente
- **Tipo/Camada**: INTEGRACAO · service-integration · CA CA-16
- **Invariante**: RN-10: antes do primeiro envio de credencial pela tela, a resolução de configuração cai no fallback do certificado legado (caminho fixo pré-existente) e as operações de cobrança continuam funcionando sem qualquer interrupção perceptível ao usuário.
- **Pré-condições**: Configuração canônica migrada mas SEM certificado próprio enviado pela tela; arquivo de certificado legado real presente em caminho de teste simulando o caminho fixo pré-existente
- **Entrada**: {"descricao": "2 cenários: fallback com arquivo legado presente vs. ausente", "valores": {"casos": ["arquivo_legado_presente", "arquivo_legado_ausente"]}}
- **Passos**: Cenário 1: com o arquivo legado presente, chamar a resolução de credenciais para uma operação (ex.: obter_token) mockando apenas a chamada de rede final.; Verificar que a credencial resolvida aponta para o arquivo legado.; Cenário 2: remover/corromper o arquivo legado e repetir a chamada.
- **Esperado**: "Cenário 1: resolução bem-sucedida usando o caminho legado, operação prossegue normalmente (equivalente ao comportamento anterior à feature). Cenário 2: erro de negócio claro, sem traceback cru."
- **Negative companion**: self — arquivo do certificado legado ausente/corrompido no caminho fixo (cenário de falha do próprio fallback) → erro de negócio claro orientando a situação, nunca uma exceção não tratada (traceback) vazando ao usuário
- **Execução real**: filesystem (fronteira HTTP mockada — provedor não é chamado)
