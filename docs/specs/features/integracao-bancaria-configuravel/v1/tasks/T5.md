## 2. Objetivo da Task
Implementar a porta para o Sicoob: cliente HTTP mTLS com URL vinda da configuração (constante `SICOOB_BOLETOS_URL` deixa de existir), token `client_credentials`, e o mapeamento bidirecional canônico↔Sicoob — único ponto que fala o dialeto do provedor.

---

## 3. Descrição Detalhada
Criar `cobranca_bancaria/adaptadores/sicoob/` com quatro módulos:

- `http.py` — `post`/`get` via `requests_pkcs12`, montando a URL a partir de `api_base_url` da config (a constante literal some do código). Headers (`Authorization: Bearer`, `client_id`), timeouts (30s token / 60s operações) num só lugar.
- `auth.py` — token `client_credentials` com `auth_url` da config canônica. Sem cache (D4).
- `mapeamento.py` — tradução nos dois sentidos: `BoletoCanonico` → payload Sicoob (`numeroCliente`, `codigoModalidade`, `numeroContaCorrente`, `codigoEspecieDocumento`, `identificacaoEmissaoBoleto`, `mensagensInstrucao`, `pagador{}`); resposta Sicoob → `ResultadoEmissao`/`ResultadoConsulta` (`nossoNumero`, `linhaDigitavel`, `codigoBarras`, `qrCode`, `pdfBoleto`, `situacao`). Mapa `situacaoBoleto`→`SituacaoBoleto` preservando o cru; normalização de UF/documento. Campos de `parametros_provedor` são mesclados no payload **sem** passar pelo núcleo (CT-010). `mapeamento.py` **não** importa `frappe`.
- `adapter.py` — `AdaptadorSicoob(AdaptadorCobrancaBancaria)` compõe os três acima e usa `materializar_certificado` por operação (D4).

### 6.6 Detalhamento dos Casos de Teste

#### CT-010 — Mapeamento canônico→provedor não expõe vocabulário do provedor no núcleo (campo sem equivalente vai para escape)
- **Tipo/Camada**: UNITARIO · unit · CA CA-17
- **Invariante**: ADR-0001: nenhum campo, URL ou vocabulário específico do provedor cruza a porta AdaptadorCobrancaBancaria; um campo canônico sem equivalente direto no provedor é roteado para o escape de parâmetros por provedor, nunca inventado nem descartado silenciosamente.
- **Pré-condições**: Dataclass canônica de boleto com campo de escape de parâmetros por provedor já modelado
- **Entrada**: {"descricao": "Boleto canônico com 1 campo core + 1 campo em escape_parametros_provedor", "valores": {"boleto_canonico": {"valor": 1500.0, "escape_parametros_provedor": {"codigoNegativacao": 3}}}}
- **Passos**: Chamar a função de tradução canônico→payload do adaptador Sicoob com o boleto canônico.; Inspecionar o payload resultante.
- **Esperado**: "payload['valor'] == 1500.00 (traduzido do campo canônico) E payload['codigoNegativacao'] == 3 (originado do escape, não hardcoded no núcleo) — o tipo canônico do boleto não tem nenhum atributo chamado 'codigoNegativacao'."
- **Negative companion**: self — objeto canônico de boleto com um campo extra não mapeado para nenhuma chave do payload Sicoob → o campo extra aparece apenas no escape de parâmetros por provedor do payload traduzido, e o núcleo (tipos canônicos) não referencia nenhuma chave em c
- **Execução real**: none (fronteira HTTP mockada — provedor não é chamado)
