## 2. Objetivo da Task
Migrar `consultar_boleto_sicoob` para o caminho canônico (leitura pura — menor risco), removendo HTTP/URL/config duplicada do módulo e preservando a assinatura e as chaves de resposta.

---

## 3. Descrição Detalhada
Modificar `cobranca_sicoob/consulta.py`: substituir `pkcs12_get`, `SICOOB_BOLETOS_URL`, `_obter_configuracao_ativa` e os extratores de JSON cru por: `resolver_credenciais()` → `obter_adaptador()` → `adaptador.consultar(ref)` → persistência a partir do `ResultadoConsulta` canônico. A assinatura `@frappe.whitelist()` e o shape da resposta são preservados (delega a `sincronizar_status_pagamento_sicoob`, portado em T9 — durante a transição, consulta pode conviver com a sincronização ainda-crua até T9). Consulta é leitura pura: não altera o boleto no provedor.

Primeira operação do estrangulamento — valida o mapeamento canônico com dano zero em caso de erro.

### 6.6 Detalhamento dos Casos de Teste

#### CT-107 — consultar_boleto_sicoob — equivalência para situação 'EM ABERTO'
- **Tipo/Camada**: INTEGRACAO · service-integration · CA CA-17
- **Invariante**: Dado o mesmo JSON cru do provedor com situacaoBoleto 'EM ABERTO', o resultado persistido na Cobranca e o conjunto de chaves da resposta de consultar_boleto_sicoob são idênticos ao comportamento pré-refactor.
- **Pré-condições**: Cobranca com numero_cliente_sicoob, codigo_modalidade_sicoob e nosso_numero preenchidos; Configuracao Integracao Bancaria ativa válida (ou fallback legado) presente; Certificado não vencido
- **Entrada**: {"descricao": "Mock do cliente HTTP centralizado (cobranca_bancaria/adaptadores/sicoob/http.py) simulando token + consulta", "valores": {"token_response": {"status_code": 200, "json": {"access_token": "tok123", "expires_in": 3600}}, "consulta_response": {"status_code": 200, "json": {"resultado": {"situacaoBoleto": "EM ABERTO", "nossoNumero": "00012345"}}}}}
- **Passos**: Preparar fixtures (Cobranca, configuração ativa); Patchar requests_pkcs12.post/get no módulo http.py do adaptador Sicoob; Chamar consultar_boleto_sicoob(cobranca.name); Reler a Cobranca do banco
- **Esperado**: "Retorno é um dict com EXATAMENTE as chaves {success, cobranca_id, situacao_boleto_sicoob, pagamento_confirmado, status_cobranca, valor_pago, data_pagamento, boleto_sicoob} (sem chave a mais/a menos); retorno['success'] is True; retorno['pagamento_confirmado'] is False; Cobranca recarregada tem pagamento_confirmado=0, status_cobranca em ('Pendente','Vencida') conforme data_vencimento, data_pagamen
- **Negative companion**: CT-110 — nenhuma configuração bancária ativa (nem canônica nem legada) → success:False com error_code CONFIGURACAO_AUSENTE/CERTIFICADO_LEGADO_INDISPONIVEL, sem nenhuma chamada HTTP
- **Execução real**: db (fronteira HTTP mockada — provedor não é chamado)

#### CT-113 — consultar_boleto_sicoob — sem nosso_numero é recusado como erro de negócio antes de qualquer HTTP
- **Tipo/Camada**: INTEGRACAO · service-integration · CA CA-17
- **Invariante**: Cobrança sem `nosso_numero` é recusada como erro de negócio ANTES de qualquer chamada ao provedor (regressão de MED-001): a consulta só ocorre após a emissão (Opção A), quando sempre há `nosso_numero`; sem ele, jamais se monta uma query malformada (valor sob a chave 'nossoNumero' errada).
- **Pré-condições**: Configuração canônica ativa válida presente; Cobranca com `nosso_numero` vazio
- **Entrada**: {"descricao": "Nenhum mock HTTP deve ser chamado — falta de nosso_numero recusa antes do transporte", "valores": {"nosso_numero": ""}}
- **Passos**: Preparar configuração canônica ativa; Criar Cobranca com nosso_numero vazio; Patchar requests_pkcs12.post/get; Chamar consultar_boleto_sicoob(cobranca.name)
- **Esperado**: "retorno['success'] is False; retorno['cobranca_id'] == cobranca.name; retorno['error_code'] == 'SICOOB_CONSULTA_SEM_NOSSO_NUMERO'; mock_post.assert_not_called() e mock_get.assert_not_called() (nem token nem GET de consulta disparados)."
- **Negative companion**: self — este é o caso negativo/de guarda (companion de CT-107/CT-108, que sempre têm nosso_numero) → ver resultado_esperado
- **Execução real**: db (fronteira HTTP mockada — provedor não é chamado)
