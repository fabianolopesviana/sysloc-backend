## 2. Objetivo da Task
Capturar, com as regras originais ainda ativas, a referência de comportamento que servirá de critério de equivalência para as migrações das T5 e T6.

---

## 3. Descrição Detalhada
Esta task **precede obrigatoriamente** T5 e T6. A RN-08 exige comprovar equivalência antes de desativar a origem, e sem referência capturada com o original ativo não há contra o que comparar — a regra vira declaração vazia.

**Regra de agregação (metragem)**: capturar o valor produzido para um conjunto representativo de entradas — imóvel sem cômodos, com um cômodo, com vários, e com metragem nula em algum. A referência é o valor, versionado no teste.

**Regra que gera documento (contrato)**: capturar o **texto extraído** do PDF gerado pela regra original, não os bytes. O artefato carrega metadados de geração que variam a cada execução; comparação binária acusaria diferença onde não há. Versionar a referência textual.

Nenhuma regra é migrada nesta task — a entrega é exclusivamente a rede de referência.

## 6. Testes

### 6.0 Padrões de Teste (detectados)
- **Framework**: `FrappeTestCase` (unittest), transação com rollback por teste
- **Convenção de nomes**: `test_<assunto>_<cenario>` em `tests/test_caracterizacao_*.py`
- **Fixture/Setup**: criação real de `Imovel` com cômodos e de `Contrato`, via `frappe.get_doc(...).insert()`
- **Mocks**: nenhum — a captura precisa observar o comportamento real da regra original

### 6.1 a 6.6 — Natureza desta task

A entrega **é** a rede de testes: os arquivos de caracterização são o artefato, não a verificação dele. Os casos que consomem essas referências pertencem às tasks que migram cada regra — `CT-012`, `CT-013` e `CT-014` na **T5**, `CT-015` na **T6** — e não são duplicados aqui, pela regra de deduplicação.

**Critério de saída verificável**: as referências existem, são versionadas, e foram produzidas com os Server Scripts originais ativos. Executar os testes desta task contra o estado atual deve passar — é a definição de "referência fiel".

## 7. Notas / Observações

**Ordem obrigatória entre tasks** (levantada no challenge): toda task que migra uma regra depende desta. Se a decomposição invertesse a ordem, a RN-08 não teria como ser satisfeita.

**A referência reflete o comportamento atual, inclusive defeitos.** Aceito deliberadamente: o objetivo da v1 é migrar sem alterar comportamento; corrigir defeito herdado é escopo de outra versão.
