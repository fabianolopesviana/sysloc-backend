## 4. Detalhes de Implementação

### 4.1 Contexto do defeito

`attach_files_to_document` roda no `on_update` de todo documento. Para cada campo `Attach` cujo valor comece com `/files` ou `/private/files`, ele:

1. procura `File` com aquele `file_url` **vinculado a este documento** → se existe, `continue`;
2. procura `File` "solto" (sem `attached_to_*`) com aquele `file_url` → se existe, adota e ajusta `is_private` pela URL;
3. **senão, cria um `File` novo** — `frappe.get_doc(doctype="File", file_url=value, attached_to_*=...)` — **sem passar `is_private`**.

No caso 3 o registro nasce `is_private = 0`, e o Frappe materializa o binário em `public/files/`, servido pelo nginx sem autenticação.

O app cai no caso 3 porque `certificado_arquivo` está em `CAMPOS_COPIAVEIS` (linha ~115) e o valor copiado aponta para um `File` vinculado a **outro** registro.

**Incidente**: 2026-07-21 16:05:26, na ativação que migrou o certificado para o Attach. `/files/certificado.pfx` acessível sem sessão por ~12 min, conteúdo idêntico ao privado. Nenhum acesso externo (auditoria do `access.log`). Contido manualmente.
